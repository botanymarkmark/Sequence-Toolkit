序列工具箱 —— 上传到 GitHub 的说明
========================================

这个文件夹里有两部分，分别对应 GitHub 的两个地方，**不要混在一起上传**：

  1-仓库文件\         → 拖到 GitHub 仓库页面（这是源码，49 个文件）
  2-Release附件\      → 在"发布 Release"时作为附件上传（这是编译好的 exe，不进仓库）


────────────────────────────────────────
第一步：在 GitHub 上新建仓库
────────────────────────────────────────
1. 打开 https://github.com/new
2. Repository name 填：  sequence-toolkit
3. Description 可以填：  序列工具箱 —— FASTA/GenBank 合并、转换、命名规范化与 NCBI 批量下载（Windows 免安装）
4. 选  Public
5. **下面三个勾选框一个都不要勾**（Add a README / Add .gitignore / Choose a license）——
   我们的文件夹里已经有 README.md、.gitignore 和 LICENSE 了，勾了会冲突
6. 点  Create repository


────────────────────────────────────────
第二步：上传源码
────────────────────────────────────────
1. 新建成功后，页面上有一行小字链接：
      "uploading an existing file"   ← 点它
   （或者直接访问 https://github.com/你的用户名/sequence-toolkit/upload/main）

2. 打开本文件夹里的  1-仓库文件\  ，**全选里面的所有内容**（Ctrl+A），
   一起拖到网页中间的拖拽区域。

   ★ 重要：请拖拽"文件夹"（docs、seq_toolkit、tests）而不是逐个文件，
     这样目录结构才能保持正确。

   ★ 注意两个隐藏的配置文件：本文件夹里有一个  .gitattributes  和一个  .gitignore
     （文件名以点开头，Windows 资源管理器里能正常看到）。
     上传完成后请在网页的文件列表里确认这两个文件**在**，如果没有，
     就把它们单独再拖一次。它们负责统一换行符和排除缓存文件。

3. 下方 "Commit changes" 的说明框里可以填：
      Initial commit: 序列工具箱 v1.0.0
   然后点  Commit changes


────────────────────────────────────────
第三步：发布 Release 并挂上 exe
────────────────────────────────────────
1. 回到仓库首页，右侧栏找到  Releases  → 点  Create a new release

2. 点  "Choose a tag"  然后输入：  v1.0.0
   再点  "Create new tag: v1.0.0 on publish"

3. Release title 填：  序列工具箱 v1.0.0

4. 描述框里可以粘贴：

      Windows 免安装单文件程序，约 10 MB，双击即用，无需安装 Python 或任何依赖。

      功能：
      - 合并 / 转换：合并 FASTA、合并 GenBank、GenBank 转 FASTA；
        可合并为单个文件，也可"每个输入文件各输出一个文件"批量转换
      - 重命名 / 拆分：按 > 行内容改写序列名（登录号 / 物种名 / 登录号_物种名），
        也可按序列拆成单文件、或批量重命名磁盘文件
      - 检索与批量下载：按物种名 / 属名检索 NCBI，筛长度、完整基因组、RefSeq；
        勾选后批量下载，下载产物为逐条 .fasta / .gb 与合并文件；登录号可批量导出为 .txt / .csv
      - 按登录号下载：粘贴、导入文本、或从已有序列文件里自动提取登录号

      首次使用请到「设置」填写 NCBI 邮箱（NCBI 的硬性要求）。
      国内直连 NCBI 经常超时，建议同时填写代理服务器地址（例如 Clash 默认的 http://127.0.0.1:7897）。

5. 把  2-Release附件\序列工具箱.exe  拖到页面底部的
   "Attach binaries by dropping them here or selecting them"  区域

6. 点  Publish release


────────────────────────────────────────
关于提交历史（重要，请读一下）
────────────────────────────────────────
用网页上传的方式，GitHub 会把所有文件记成**一次提交**。
本项目在本地开发时累积的 67 次提交记录和 v1.0.0 标签**不会**一起上传上去，
也就是说 GitHub 上看不到逐步修改的过程。

如果你在意这段历史，有两个办法：

  A. 保持现状即可。仓库内容完整可用，功能与测试一个不少。

  B. 以后想补上历史：在本地这份项目目录里执行（需要装 Git）
       cd "C:\Users\33411\一些非常实用的基因组分析数据小插件"
       git remote add origin https://github.com/你的用户名/sequence-toolkit.git
       git push -u origin main --force
       git push origin v1.0.0
     这样会把完整的提交历史与标签覆盖上去。

     注意：--force 会覆盖网页上传的那次提交，所以这一步要在你没在网页上
     改过文件的前提下做，否则会丢掉网页上的改动。
