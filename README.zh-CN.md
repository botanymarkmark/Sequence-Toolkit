# 序列工具箱（Sequence Toolkit）

[English](README.md) | **中文**

把基因组学日常最琐碎的几件事整合进一个免安装的 Windows 小程序：

1. **合并 / 转换** —— 合并 FASTA、合并 GenBank、GenBank 转 FASTA（后缀名混乱也能自动识别）；
   既可以合并成一个文件，也可以**每个输入文件各输出一个文件**
2. **重命名 / 拆分** —— 按 `>` 行内容改写序列名，也可把序列拆成单文件、或批量重命名磁盘文件
3. **检索与批量下载** —— 按物种名 / 属名检索 NCBI，筛长度、完整基因组、RefSeq，勾选后批量下载；
   下载产物为逐条 `登录号.fasta` / `登录号.gb` 与合并文件，登录号可批量导出为 `.txt` / `.csv`
4. **按登录号下载** —— 粘贴、导入文本、或从已有序列文件里自动提取登录号
5. **物种名清洗** —— 把一批学名交给 TNRS 在线服务，拿到接受名、匹配状态与来源数据库，
   可导出 CSV，也可把接受名写回 FASTA / GenBank
6. **进化树生成** —— 只要学名，调用本机的 R + V.PhyloMaker2 生成 Newick 系统树，
   界面内直接预览

## 三种命名规则

| 规则 | 示例 |
|---|---|
| 登录号 | `ON929859.1` |
| 物种名 | `Salsola_pellucida` |
| 登录号_物种名 | `ON929859.1_Salsola_pellucida` |

空格一律替换为 `_`。**只有当整批渲染出的文件名会撞车时才追加流水号**（`_1`、`_2`），
因此「登录号」与「登录号_物种名」两种规则通常不加号（登录号本身已唯一），
只有「物种名」规则在同一物种有多条序列时会加号，避免出现同名文件被覆盖。

检索结果页支持把登录号**批量导出**为 `.txt`（一行一个）或 `.csv`（带表头，列与结果表格一致）；
勾选了行就导出勾选的，没勾选就导出表格显示的全部，并在日志里写明实际导出的条数。

## 合并 / 转换的两种输出方式

「合并 / 转换」页的 **输出方式** 单选决定产物形态（**用户使用后新增**）：

| 输出方式 | 产物 | 输出选择器 |
|---|---|---|
| 合并为单个文件（默认） | 所有输入合并成**一个**文件 | 选一个输出**文件** |
| **每个输入文件各输出一个文件** | 一个输入文件 → 一个输出文件（数量由输入文件数决定） | 选一个输出**目录** |

批量模式的规则：

- **输出文件名 = 原文件主干 + 目标格式后缀**：`样本.gbk` → `样本.fasta`，`样本.gbk.gz` → `样本.fasta`
  （两层后缀一起剥掉，不会得到 `样本.gbk.fasta`）
- **文件内序列名套用本页「命名规则」**：选「登录号_物种名」就得到 `>ON929859.1_Salsola_pellucida`
- **每个文件独立处理**：文件内多条记录仍写进同一个输出文件，只是各自转换；
  「按登录号去重」与流水号（`_1`、`_2`）的作用域都**只在单个文件内**——两个文件里各有一条同物种序列互不影响
- 只有 `CONTIG` 记录（未组装、没有 `ORIGIN`）的文件**不产出空文件**，记 WARN 后跳过
- 单个文件读不动/写不出只记 ERROR 并跳过，**不中断整批**
- 输出目录里已有同名文件时**绝不静默覆盖**：内容逐字节相同 ⇒ 跳过不再写一份，内容不同 ⇒ 让位 `_1` 并告警

## 物种名清洗与进化树生成

### 物种名清洗（TNRS）

把一批学名粘进「物种名清洗」页，点「开始清洗」即可拿到每个名称的接受名、匹配状态与
来源数据库，支持导出 CSV，也可把接受名写回 FASTA / GenBank 文件。

- 走 TNRS 在线服务（`https://tnrsapi.xyz/tnrs_api.php`），单次请求最多 5000 个名称，
  超出会自动分批；默认名录来源为 WCVP + WFO。
- **未匹配的名称不会消失**：它们会以「未匹配」状态留在表里，并在结果表**下方**汇总提示。
- 「匹配模式」可选 `best`（只取最佳匹配，默认）或 `all`（返回全部候选）。选 `all` 时
  一个名称可能对应多行，界面会写明「N 个名称 → M 行结果」。
- 写回文件时**绝不覆盖原文件**：输出到指定目录，文件名加 `_cleaned` 后缀
  （`样本.fasta` → `样本_cleaned.fasta`）。
- **「名录来源」/「匹配模式」两个下拉框的选择只在本次会话内有效**：它们只在构建面板时
  读取一次，**不会写回** `settings.json`，重启后回到上次保存的值；需要在启动时就指定，
  请直接编辑 `%APPDATA%\seq_toolkit\settings.json` 的 `tnrs_sources` / `tnrs_matches`。

### 进化树生成（V.PhyloMaker2）

把物种学名粘进「进化树生成」页，选命名系统与绑定场景，点「生成进化树」即可得到
Newick 树文件并在界面内预览。**只需要学名**——属名与科名由程序自动补齐。

- 需要本机安装 R 与 R 包 V.PhyloMaker2（可选外部依赖，不随本程序打包）：
  1. 安装 R：<https://cran.r-project.org/bin/windows/base/>（默认安装，无需管理员权限）
  2. 在 R 里执行：`install.packages("remotes")` 然后
     `remotes::install_github("jinyizju/V.PhyloMaker2")`
  3. 回到本程序「设置」页填写 `Rscript.exe` 路径，或点「检测 R 环境」自动查找
- 命名系统为 **TPL**（The Plant List，74,529 种，默认）/ **LCVP**（73,420 种）/
  **WP**（World Plants，72,570 种）——这是 V.PhyloMaker2 内置的三套系统树。
- 绑定场景 S1/S2/S3 分别对应"只绑定到属节点 / 科内随机 / 属内随机"，默认 S3。
- **未能绑定到系统树的物种会被明确列出**（拼写错误或名录未收录），不会悄悄消失。
- 首次生成需要载入巨型系统树，实测 7 个物种约 17 秒；物种越多越慢。
- **「命名系统」/「绑定场景」两个下拉框的选择只在本次会话内有效**：它们只在构建面板时
  读取一次，**不会写回** `settings.json`，重启后回到上次保存的值；需要在启动时就指定，
  请直接编辑 `%APPDATA%\seq_toolkit\settings.json` 的 `phylo_system` / `phylo_scenario`。

### 这两个功能的已知限制

- **建树依赖本机的 R 与 V.PhyloMaker2**：两者都是**可选外部依赖，不随 exe 打包**，
  没装也不影响其余六个标签页。缺依赖时程序给出的是可复制的三步安装指引（装 R →
  `install.packages("remotes")` + `remotes::install_github("jinyizju/V.PhyloMaker2")` →
  在「设置」页填 `Rscript.exe` 路径或点「检测 R 环境」自动查找），不是异常栈；
  「设置」页另有「复制安装指引」按钮，因为这几行命令要粘到 R 里执行。
- **命名系统只有 TPL / LCVP / WP 三套内置系统树**（物种数见上），**不是** APG III /
  APG IV——V.PhyloMaker2 里没有这两个选项，界面也不提供，免得用户以为能选。
- **绑定场景 S1 / S2 / S3 决定未收录物种挂到系统树的哪一层**：S1 只绑定到**属节点**、
  S2 在**科内**按随机分辨率绑定、S3 在**属内**按随机分辨率绑定（默认 S3）。物种本身已
  收录时三者结果相同，差别只体现在需要回退到属/科一级的物种上。
- **未能绑定到系统树的物种会被明确列出**，提示里同时给出「输入 N 个 / 入树 M 个」，
  绝不悄悄少几个物种还让用户以为成功——这是本项目「绝不静默」原则在建树上的体现：
  R 自己会打印**两行**——先是 `[1] "Note: 1 taxa fail to be binded to the tree,"`，
  再逐个打印被丢掉的物种（实测 R 4.6.1：`[1] "Xyzzy_foobar"`）——本程序把两行都抓回来，
  在界面醒目位置与日志（WARN）里都报出来。
- **首次生成要载入巨型系统树**（七万多种），实测 7 个物种约 17 秒；物种越多越慢，
  上千种可能数分钟。因此建树在后台线程执行、可取消，超时上限 600 秒。
- **名称回写只支持未压缩的 FASTA / GenBank**：`.gz` 与非 UTF-8 编码（例如中文 Windows
  上常见的 GBK）的文件会被**显式拒绝**，并提示先解压 / 转码再试。这是刻意的安全取舍：
  用「忽略解码错误」的方式读这两类文件不会报错，只会写出一个内容已经损坏、却看起来
  处理成功的 `_cleaned` 产物——宁可让用户多走一步，也不产出坏文件。
- **「部分匹配」的行也会参与名称回写**：规格只排除「未匹配」，所以得分为 1 以下是
  「部分匹配」的行，其接受名同样会被写进文件。界面在回写前会先提示有多少行属于这种
  情况，避免用户对「某个名字为什么被改成了不完全等于它的接受名」莫名其妙。

## 安装与运行

从本仓库的 [Releases](../../releases) 页面下载 `序列工具箱.exe`，双击即可，**无需安装 Python 或任何依赖**。

首次使用请到「设置」填写 **NCBI 邮箱**（NCBI 的硬性要求）。国内直连 NCBI 经常超时，建议同时填写代理服务器地址（例如 Clash 默认的 `http://127.0.0.1:7897`）。

> 若双击后没有反应，多半是杀毒软件误报拦截；加入白名单即可，或按下方「从源码运行」自行打包。

## 从源码运行

```bash
python -m pip install -r requirements.txt
python main.py
```

## 测试

```bash
python -m pytest -v
```

共 556 项，其中 **555 项通过、1 项既有失败**：`tests/test_ncbi.py::test_adjacent_requests_hold_the_interval_with_the_default_clock`
（请求时间轴重建的浮点残差，与本工具箱的功能无关，已决定暂不修）。判断标准是
「本任务相关测试全绿、既有通过数不减少」，因此不要把这一项当成新增缺陷。
测试全程离线：TNRS 请求走注入的替身，R 子进程走注入的接缝（`_spawn` / `_kill_process_tree`），
不会真的联网或启动 R（真实环境的验收记录见 `docs/acceptance.md`）。

## 打包为单文件 exe

```bash
python -m pip install -r requirements.txt
python -m PyInstaller --clean --noconfirm build.spec
```

产物为 `dist/序列工具箱.exe`。若杀毒软件误报，请将其加入白名单；也可改用 `--onedir` 模式
（把 `build.spec` 中 `EXE(...)` 的 `onefile` 相关参数去掉），启动更快但产出是一个文件夹。

## 已知限制

- **GenBank 输出的 LOCUS 名称字段只有 16 列。** 当目标名称超过 16 个字符时，输出的 `LOCUS` 名保持原值不变（避免破坏列对齐导致下游解析截断），改名映射会写入日志。
- **未组装记录（只有 `CONTIG`、没有 `ORIGIN`）无法导出序列**，会被列入异常清单并跳过，不会静默丢弃。
- **"只要完整基因组"是本地筛选**：NCBI 服务端没有可信字段，本工具按定义行关键词判断。
- **不做并发下载**：速度瓶颈在 NCBI 的速率限制，单线程顺序下载已足够，且更不容易触发封禁。

## 目录结构

```
main.py                  程序入口
build.spec               PyInstaller 打包配置
seq_toolkit/
  model.py               统一数据模型 SequenceRecord
  textio.py              UTF-8 / BOM / .gz 文本打开
  format_detect.py       格式识别（内容优先于后缀）
  fasta_io.py            FASTA 读写
  genbank_io.py          GenBank 读写（原始块保真）
  naming.py              命名规则引擎（纯函数）
  pipeline.py            合并 / 转换 / 拆分 / 磁盘改名编排
  ncbi.py                E-utilities 客户端
  tnrs.py                物种名清洗（TNRS 请求构造、分批、解析、CSV、回写）
  phylo.py               系统树生成（Rscript 探测、R 脚本渲染、未入树解析、Newick 解析）
  settings.py            配置持久化
  applog.py              日志与异常清单
  gui/                   Tkinter 界面（tab_tnrs.py 清洗页、tab_phylo.py 建树页、tree_canvas.py 树预览）
tests/                   pytest 测试
docs/acceptance.md       端到端验收记录（既有 28 项 + 功能 7/8 的 12 项）
```
